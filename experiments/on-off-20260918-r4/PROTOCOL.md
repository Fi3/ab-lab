## Qualified repair boundaries

Host commands and native shell commands resolve a run-local Codex launcher.
It pins model/effort/subscription, rejects contradictory overrides and removes
API environment variables. The Bash hook also strips variables restored by
shell startup. No frozen repository instruction or source file contains this
instrumentation. Child native histories rooted in the owned checkout contribute
their increasing per-conversation counters once, excluding already-priced
parent threads. Launch plus resume is not two independent cumulative charges.
Missing child coverage or model mismatch invalidates a comparison.

Native command execution retains its existing restricted sandbox. A real probe
shows a nested CLI can fail before agent startup because its local state is
read-only. The ordinary `codex doctor` confirms stored ChatGPT authentication;
no broader permission grant or credential copy is made. Such a recorded
pre-agent failure is not successful real-agent verification and is not charged
invented tokens. This limitation must remain visible in the final comparison.

An author may discover that a requested feature already exists. With no source
change, independent review checks the complete requested behavior and tests,
not just the empty diff. Findings still require repairs and re-review. A genuinely
unchanged approved feature receives an explicit verification-only empty final
commit. Both groups use exactly this same completion boundary. It does not let
an empty diff pass automatically or waive any required feature/scoring check.

The earlier Git-write preflight and priced-interruption repairs stay in place.
Only the owned checkout and its Git directory are writable for native write
roles; review remains read-only. Discretionary C25 interruption requires usage
covering the selected host request, followed by passive final usage drainage.
